# ХимПро — Timeweb Cloud App Platform (тестовая версия)

Приложение Flask для учёта промышленной химии: номенклатура, рецептуры и технологические карты, склад и партии, выпуск, отгрузки, сроки годности, двусторонняя прослеживаемость, пользователи и журнал.

## Установка только через веб-панель

1. В GitHub через сайт создайте **закрытый (Private)** репозиторий `chempro`.
2. Выберите **Add file → Upload files**, загрузите **содержимое** этой папки (Dockerfile, app.py, entrypoint.py, requirements.txt, .gitignore, .dockerignore), затем нажмите **Commit changes**. Не загружайте ZIP вместо файлов.
3. Откройте https://timeweb.cloud/ → **App Platform → Создать**.
4. Подключите GitHub, выберите репозиторий `chempro`, тип/фреймворк **Dockerfile**, каталог проекта `/` (корень).
5. Выберите регион и конфигурацию. Укажите путь проверки состояния `/health`, если панель предлагает этот параметр.
6. В разделе переменных окружения добавьте:
   - `SECRET_KEY`: случайная строка длиной минимум 32 символа (сгенерируйте через менеджер паролей);
   - `ADMIN_PASSWORD`: уникальный пароль длиной минимум 12 символов;
   - `CHEM_DB`: `/app/data/chem.db` (необязательно, это значение по умолчанию).
7. Нажмите **Запустить деплой**. После успешного запуска откройте выданный платформой адрес. Логин: `admin`, пароль: ваш `ADMIN_PASSWORD`.
8. Для обновления файлов используйте GitHub → **Add file → Upload files**; включите автодеплой в настройках приложения, если он доступен.

## Критически важные ограничения

- Это **тестовая демонстрация**, не система для реальных производственных данных.
- SQLite хранится **в файловой системе контейнера**. При повторном развёртывании, пересоздании или миграции контейнера данные могут быть потеряны. Приложение не подключено к управляемой PostgreSQL. Не вводите реальные рецептуры, персональные данные, отгрузки и документы.
- `ADMIN_PASSWORD` применяется только при первом создании базы. Изменение переменной не сбрасывает пароль существующего пользователя.
- Необходимы отдельные доработки: постоянная PostgreSQL, миграции, резервное копирование и тест восстановления, управление сессиями, тесты прав доступа, защита от перебора паролей, проверка бизнес-правил и полноценные испытания.
- Код рассчитан на один экземпляр приложения, не включайте горизонтальное масштабирование.
- Пароли/секреты вводите **только в панели Timeweb**, не сохраняйте в GitHub.
