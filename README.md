# ХимПро v4 — производственные задания

Развивает v3 (ОТК, склад, сроки годности, рецептуры, партии, прослеживаемость).

## Новое
- `/work-orders`: создание черновика задания технологом/администратором, утверждение и отмена.
- Выполнение утверждённого задания оператором/администратором через `/production?order_id=N`.
- Связь задания с выпущенной партией и журналом прослеживаемости.
- Проверка утверждённой рецептуры, номера партии и планового количества при исполнении.
- Записи аудита для создания/утверждения/отмены и выпуска.
- Схема `work_orders` создаётся автоматически при `init()` без удаления существующих таблиц.

**Ограничение:** это планирование без резервирования сырья. Доступность проверяется непосредственно при проведении выпуска, когда сырьё списывается по FEFO. Ручной выпуск без задания оставлен для совместимости с v3.

## Обновление через GitHub
1. Сделайте резервную копию БД и исходников.
2. Загрузите содержимое папки `chempro_v4` в корень репозитория GitHub, заменив одноимённые файлы. Не загружайте саму папку как вложенную директорию.
3. После восстановления Timeweb запустите деплой; путь healthcheck — `/health`.
4. Проверьте `/health`, вход, задания, ОТК, выпуск и прослеживаемость.

Для эксплуатации нужны постоянное хранилище БД, резервные копии и полноценная проверка прав/безопасности. Это прототип, не валидированная производственная MES.

## v5 — План производства и расчёт потребности (MRP-lite)

- Новый раздел `/planning` и ссылка в меню после авторизации.
- Горизонт планирования от 1 до 365 дней.
- Список утверждённых невыполненных заданий по сроку выпуска; просроченные даты выделяются.
- Суммарная потребность по материалам из утверждённых рецептур, сопоставление с остатками сырья, разрешённого ОТК и годного **на сегодня**.
- Расчёт дефицита по каждому материалу. Отчёт только для чтения, существующие данные не изменяет.

**Ограничения:** это предварительный MRP-отчёт без резервирования, учёта будущих поставок, временной доступности партий, закупок и проверки единиц измерения. Если сырьё и выпуск имеют разные единицы, проценты рецептуры могут быть неприменимы без конверсии. Не используйте отчёт как единственный источник решения о выпуске. Выполнение задания по-прежнему проверяет наличие сырья атомарно.

Обновление с v4: замените `app.py` (остальные файлы включены для полноты). Перед обновлением сохраните базу данных; не развёртывайте новую версию в Timeweb, пока проблема с healthcheck не решена.


## v6 — Резервирование и снабжение
- В утверждённом производственном задании доступны кнопки «Резервировать» и «Снять резерв».
- FEFO-резервирование конкретных разрешённых партий с учётом срока годности на дату выпуска.
- При отмене задания резерв снимается; при выполнении списываются зарезервированные партии.
- Незарезервированный выпуск не использует чужие резервы.
- Новый раздел `/supply`: список резервов, заявки на закупку, статусы заявок.
- Новые таблицы создаются при старте без удаления прежних данных.

Ограничения: это MVP, не полноценный закупочный контур; нет поставщиков, заказов поставщику, автоматического прихода, денежных расчётов. SQLite требует постоянного тома и резервного копирования. В версии v6 отчёт MRP учитывает свободный остаток, но суммарная потребность включает зарезервированные задания — показатель дефицита для них может быть завышен. Для производственной эксплуатации необходимы испытания, аудит и согласованные правила качества.


## v7: Закупки и поставщики

Новый раздел `/procurement`: справочник поставщиков, заказы, частичные приходы, связь с заявками на закупку и партиями сырья. Приход автоматически создаёт складскую партию в карантине и движение; разрешение выполняется отдельно ОТК. Данные создаются в SQLite через `CREATE TABLE IF NOT EXISTS` при `init()`.

**Обновление:** сначала сделайте резервную копию базы данных, затем замените файлы проекта через GitHub. Не выкладывайте действующую базу или секреты в репозиторий. Требуется постоянный том для `/app/data` — иначе данные могут потеряться при пересоздании контейнера.

**Ограничения:** нет учёта валют, цен, НДС, договоров, входного контроля документов и строгой сверки объёмов заявки с несколькими заказами. Это прототип, не валидированная промышленная ERP.
