# ХимПро v29 — возвраты готовой продукции от клиентов

## Новые маршруты
- `/tsd/customer-return` — регистрация QR ранее отгруженной тары (ScanWedge Keystroke + Enter).
- `/quality/customer-returns` — журнал карантинных возвратов.
- `/quality/customer-returns/<id>` — решение ОТК: забраковать либо разрешить повторный оборот.

## Складская логика
- При регистрации возврата остатки `lots` и `containers` **не меняются**: продукция изолирована и недоступна к отгрузке.
- Повторный возврат одной и той же тары запрещён; повторный запрос с тем же токеном идемпотентен.
- При положительном решении ОТК проверяется исходная партия (`released`, не просрочена), в одной транзакции восстанавливаются количество в таре, количество партии и движение.
- При браковке остатки не меняются. Для физической утилизации нужен отдельный акт (не реализован).
- Разрешение к повторному обороту **не заменяет** реальную лабораторную проверку: сотрудник ОТК должен выполнить её и указать основание решения.

## Ограничения
Только полная тара, ранее отгруженная через QR-модуль v28. Повторные циклы отгрузки/возврата той же тары после разрешения в v29 не поддержаны: `UNIQUE(container_id)` блокирует следующий возврат. Старые отгрузки без QR не поддержаны. Статус карантина учитывается в журнале возвратов, но не изменяет статус исходной партии. Права: приёмка admin/warehouse; решение admin/quality.

## Развёртывание
Перед обновлением сохраните резервную копию SQLite, проверьте на тестовой базе и Urovo CT48. `init()` создаёт таблицы при запуске через `entrypoint.py`. Запуск `python app.py` также поддержан. Полноценное тестирование в Timeweb и на CT48 не проводилось.
