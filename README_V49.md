# lovetech v49 — плановые резервные копии и пробное восстановление

Основа v48. `backup_rotation.py` выполняет **один** цикл: SQLite Online Backup API → проверка копии → восстановление в **временную** БД → проверка восстановления → удаление старых автоматических копий сверх лимита. Работающая БД не заменяется и не изменяется. При ошибке возвращает код 1 и пишет JSON в stderr; подключите оповещения инфраструктуры по ненулевому коду.

## Запуск

```bash
python backup_rotation.py --db /app/data/chem.db --directory /app/data/backups --keep 14
python -m unittest -v test_v48_reliability.py test_v49_backup_rotation.py
```

## Ежедневный запуск (пример cron на хосте с доступом к тому и Python)

```cron
15 2 * * * cd /app && /usr/local/bin/python backup_rotation.py --db /app/data/chem.db --directory /app/data/backups --keep 14 >> /app/data/backups/backup-job.log 2>&1
```

**Cron не устанавливается приложением автоматически.** Timeweb App Platform может не предоставлять cron внутри контейнера; используйте доступный внешний планировщик/отдельный worker, который имеет доступ к постоянному тому и к скрипту. Проверьте пути и права. При контейнерном деплое добавлен `backup_rotation.py` в Dockerfile.

## Важные ограничения

- `--keep 14` означает 14 **последних копий**, не 14 календарных дней. Ротация затрагивает только файлы `lovetech-auto-*.db`; ручные файлы не удаляются.
- Если копирование или пробное восстановление не удалось, ротация не выполняется; копия с ошибкой остаётся для расследования.
- Восстановление проверяется в **изолированной временной** базе; это не проверка полного запуска Flask и не восстановление production.
- Копии на том же диске **не защищают от потери тома**. Настройте отдельную защищённую выгрузку во внешнее хранилище, шифрование, мониторинг результатов и периодическую ручную проверку восстановления.
- Файлы резервных копий содержат персональные и коммерческие данные. Не публикуйте их в GitHub и не отдавайте через публичный веб-сервер.
- Перед обновлением production сделайте отдельную ручную копию вне сервера и протестируйте v49 на тестовом стенде.
