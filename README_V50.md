# lovetech v50 — мониторинг и журнал ошибок

Основа: v49. Сохранены существующие маршруты и операции. Добавлен модуль `observability_v50.py`.

## Новое

- `GET /health/ready`: анонимная проверка доступности SQLite в **режиме чтения**. Возвращает HTTP 200 (`ready`) или 503 (`unavailable`). Не выдаёт путь к базе, структуру или данные.
- `GET /admin/monitoring`: только роль администратора; 100 последних ошибок HTTP 5xx и исключений; время UTC, идентификатор запроса, шаблон маршрута, класс ошибки, код и ID сотрудника.
- Ошибки 4xx (например, неправильный пароль, CSRF или отсутствие доступа) не пишутся в журнал. Ответ при 5xx не раскрывает traceback, SQL и внутренние пути.
- Таблица `operational_errors_v50` создаётся лениво при первой записи или открытии панели. Ранее существующие таблицы не изменяются.

## Развёртывание

Обновите исходники/Docker-образ обычным способом, предварительно сделав резервную копию SQLite. Dockerfile включает новый модуль. Проверяйте `/health/ready` внешним монитором; `GET /health` остаётся простым liveness endpoint. Ошибки и журналы не передаются внешним сервисам автоматически.

## Тестирование

`python -m unittest -v test_v50_monitoring.py` — тесты на SQLite без Flask. `python -m unittest -v test_v50_http.py` — HTTP-тесты при наличии зависимостей из requirements.txt.

## Ограничения

Нет фонового опроса, push-уведомлений, автоматической ротации таблицы ошибок или централизованного хранения логов. При полном отказе SQLite запись об ошибке может не сохраниться в БД; приложение попытается вывести сообщение в stderr. Следите за ростом таблицы и сроком хранения данных. События 4xx намеренно не собираются. Данные мониторинга требуют защиты и ограниченного доступа.
