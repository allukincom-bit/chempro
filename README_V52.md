# lovetech v52 — проверка обновлений и диагностика

Основа: v51. Добавлен `diagnostics_v52.py` — **только чтение** существующей SQLite, контроль ключевых таблиц миграций и зарегистрированных маршрутов Flask. При наличии зависимостей доступен GET-only HTTP smoke test на тестовом клиенте. Приложение не меняет статусы документов и не корректирует складские остатки.

## Установка на Timeweb

1. Сохраните резервную копию SQLite **вне сервера**.
2. Разверните v52 сначала на тестовом окружении с копией рабочей БД.
3. Запустите `python diagnostics_v52.py --db /app/data/chem.db` (без Flask).
4. Проверьте регистрацию маршрутов: `python diagnostics_v52.py --db /app/data/chem.db --routes`.
5. На тестовом стенде: `python diagnostics_v52.py --db /app/data/chem.db --http`.
6. При ненулевом коде выхода изучите JSON-отчёт и не переключайте рабочий трафик до исправления.

`--http` использует Flask test_client и GET-запросы, но **может запускать код обработчиков**; выполнять только на копии БД. Для сессии берётся существующий администратор (без пароля, только внутри тестового клиента); если такого пользователя нет, защищённые страницы пропускаются. Тест не является проверкой настоящей авторизации через браузер или Urovo CT48. Внешние HTTP-проверки реального Timeweb-развёртывания не включены.

Проверка структуры не изменяет схему: если нужных таблиц нет, надо запускать штатный `entrypoint.py`/`init()` в контролируемом обновлении после резервного копирования, затем повторить диагностику. Скрипт не пытается сам исправлять миграции.

Тесты: `python -m unittest -v test_v52_diagnostics.py`. Полные тесты HTTP требуют `pip install -r requirements.txt`.
