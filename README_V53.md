# lovetech v53 — отчёт готовности обновления

Основа: lovetech v52. Новые файлы `release_check_v53.py` и `test_v53_release.py`. Предыдущие модули и маршруты сохранены.

## Команды

```bash
python release_check_v53.py --db /app/data/chem.db --output /tmp/lovetech-v53-report.json
python release_check_v53.py --db /app/data/chem.db --backups /app/data/backups --output /tmp/lovetech-v53-report.json
python -m unittest test_v53_release.py -v
```

Код выхода: `0` — все запрошенные проверки пройдены; `1` — выявлены проблемы. Отчёт включает `ready`, `checks`, время UTC. Без `--backups` статус резервирования **не проверяется** и не учитывается в `ready`.

## Что проверяется

- SQLite: существование, integrity_check, внешние ключи и таблицы v52 (только чтение).
- Исходный `app.py`: регистрация ключевых маршрутов и наличие точных `@allowed(...)` для `/users`, `/admin/system`, `/admin/monitoring`, `/production/execution`. Это **статическая проверка**, а не доказательство безопасности всех ролей.
- Согласованность: отсутствие производственных листов без задания и партий без рецепта или складской партии.
- Опционально: свежесть и успешность последней проверенной резервной копии по статусу v51.

Проверка **не выполняет миграции**, не запускает `init()`, не отправляет POST, не меняет базу. Не проверяет реальные сценарии сканирования CT48, права через HTTP и производственные операции от начала до конца. Перед развёртыванием нужны резервная копия, тестовая база, отдельные HTTP/ролевые проверки и пробное восстановление.

## Timeweb

Разверните как прежнюю версию (Dockerfile и entrypoint.py сохранены). Перед выкладкой сделайте резервную копию SQLite, на тестовой копии выполните диагностику v52 и новый отчёт v53. JSON-отчёт сохраняйте вне каталога БД. При ненулевом коде выхода разберитесь с причинами до обновления.
