# lovetech v54 — изолированные HTTP-тесты и матрица ролей

Версия основана на v53. Приложение и рабочая SQLite не изменяются: добавлены тестовые и диагностические скрипты.

## Запуск на тестовом стенде

```bash
pip install -r requirements.txt
python -m unittest -v test_v54_static test_v54_http
python role_http_v54.py --output /tmp/lovetech-v54-http.json
```

`role_http_v54.py` создаёт **новую временную SQLite**, запускает существующий `init()`, создаёт тестовых сотрудников каждой роли и проверяет анонимный доступ, GET-маршруты и защиту POST без CSRF. По завершении временная БД удаляется. Скрипт не использует реальную базу, даже если `CHEM_DB` задан в окружении. **Не запускайте тесты параллельно в одном процессе с боевым Flask-приложением**: модуль `app` содержит глобальную переменную DB.

Маршруты матрицы: `/admin/system`, `/admin/monitoring`, `/economics/costs`, `/production/execution`, `/recipes`. Если проверка выявит расхождение фактических прав и ожидаемых, тест завершится с ошибкой — это повод проверить бизнес-правила, а не автоматически расширять доступ.

Сценарии намеренно не проводят реальные списания, приёмку, отгрузку, закрытие производственных листов или отправку форм с валидным CSRF. Это **smoke-тесты**, а не полное end-to-end покрытие. Проверка браузера Urovo CT48 проводится отдельно.

## Timeweb

1. Сделайте резервную копию SQLite.
2. Разверните ZIP на отдельном стенде с `SECRET_KEY` и `ADMIN_PASSWORD` согласно README.
3. Установите зависимости и выполните тесты, проверьте JSON-отчёт.
4. После успешной проверки разверните на рабочем сервере. Не запускайте `init()` и тесты на боевой базе в процессе обновления без отдельного плана миграции.

## Ограничения

Тесты требуют Flask и qrcode. Если они отсутствуют, HTTP unittest пропускается, а прямой CLI возвращает ошибку `dependencies_missing`. Никакие HTTP-проверки на Timeweb в сборке не проводились.
