# lovetech v55 — интеграционные сценарии производства и склада

Версия основана на v54. Новые файлы: `production_flow_v55.py`, `test_v55_static.py`. Производственные маршруты приложения не изменены: v55 добавляет регрессионную защиту, а не новую операционную функцию.

## Сценарии

- Создание черновика задания → утверждение → FEFO-резервирование двух сырьевых партий → выпуск готовой продукции в карантин.
- Проверка списаний сырья, журналов `movements` и `consumptions`, снятия резерва, закрытия задания.
- Повторная отправка выпуска не должна создавать вторую партию или повторное списание.
- Недостаточный остаток должен оставлять склад и производственные документы неизменными.
- Черновое задание нельзя выпускать, POST без CSRF отклоняется.
- Повторное резервирование не дублирует резерв, отмена задания освобождает его без списания.

## Запуск

```bash
pip install -r requirements.txt
python -m unittest -v test_v55_static
python production_flow_v55.py
python role_http_v54.py --output /tmp/v54-roles.json
```

`production_flow_v55.py` **всегда создаёт временную SQLite** и удаляет её после теста; рабочую базу не затрагивает. Проверки используют Flask test_client и тестовую сессию администратора. При отсутствии Flask или qrcode интеграционные сценарии пропускаются; исполнитель возвращает код 1, чтобы CI не считал пропуск успехом.

## Timeweb

Сначала создайте резервную копию рабочей базы. Установите зависимости и запускайте тесты в отдельном контейнере/тестовом окружении, не в работающем производственном процессе. Не указывайте боевые учётные данные. Сверьте результаты и логи перед обновлением.

## Ограничения

Проверяются прямое резервирование и выпуск по утверждённому заданию без физического TSD; отдельный сценарий подбора и выдачи тары CT48 пока не покрыт. Испытания на реальном терминале и на Timeweb не проводились. Тесты не подтверждают корректность всех модулей приложения.
