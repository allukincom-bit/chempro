# lovetech v56 — HTTP-проверки цепочки Urovo CT48

На основе v55. Производственная логика приложения не менялась. Добавлен `tsd_flow_v56.py`: шесть интеграционных сценариев на **отдельной временной SQLite** с Flask test client. Данные настоящего склада не используются.

## Проверяемая цепочка

1. Утверждённое задание и резерв 60 кг.
2. Регистрация тары QR + места хранения через `/tsd/receive` (без увеличения остатков).
3. Подбор по резерву `/tsd/pick` (без списания).
4. Выдача `/tsd/issue` (без списания).
5. Выпуск производственного листа для теста и фактическая загрузка `/tsd/load` с временем взвешивания.
6. Частичный возврат `/tsd/return` до проведения выпуска; защита от дублей, CSRF, неправильного места, превышения резерва и норматива.

**Ограничения:** не выполняется реальное сканирование лазером Urovo CT48; HTTP-клиент имитирует отправку текстового QR, как ScanWedge Keystroke. Не проверяются браузерный фокус, Enter, физическое устройство и окончательное списание при выпуске (это сценарий v55). Тесты запускаются только после установки зависимостей.

## Запуск

```bash
pip install -r requirements.txt
python -m unittest -v test_v56_static
python tsd_flow_v56.py
```

Интеграционный runner возвращает код 1 при ошибке или пропуске тестов. Для Timeweb: сперва бэкап SQLite, затем проверка в staging; не запускайте интеграционные сценарии на рабочей БД. Временная БД создаётся в каталоге ОС и удаляется после теста.

Сохраняются Dockerfile, entrypoint.py и предыдущие тесты. Для deployment используйте инструкции базового README и README_V55.md.
