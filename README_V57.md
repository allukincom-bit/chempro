# lovetech v57 — проверки жизненного цикла производственного листа

Основа: lovetech v56. Действующая производственная логика не изменена. Добавлены HTTP-интеграционные регрессионные тесты на **изолированной временной SQLite**.

## Проверяемые сценарии
1. Выдача листа с неизменяемым снимком утверждённой ТК и A4-печать.
2. Ввод измерений с отдельными временами измерения и внесения, регистрация бумажного оригинала, передача на проверку и закрытие.
3. Запрет закрытия без обязательного измерения.
4. Запрет передачи на проверку без зарегистрированного бумажного оригинала.
5. Отклонение с обоснованием, принятие технологом и закрытие.
6. Запрет закрытия с отклонённым измерением.
7. Запрет изменения закрытого листа.
8. Защита CSRF.
9. Проверка запрета записи для роли просмотра.
10. Защита от повторной регистрации бумажного оригинала.

## Запуск
```
pip install -r requirements.txt
python -m unittest -v test_v57_static
python sheet_lifecycle_v57.py
```

Интеграционный runner возвращает ненулевой код при отсутствии Flask/qrcode, пропуске тестов или ошибке. Не запускать против рабочей базы: сценарий создаёт отдельную временную SQLite, но импортирует приложение и переключает глобальную `app.DB` на неё в процессе тестирования. Запускайте тесты отдельным процессом и не параллельно с другими тестами, использующими `app.DB`.

## Timeweb
Развернуть как обычно через Dockerfile/entrypoint.py, предварительно сохранить SQLite. Сначала проверить в staging. В архиве нет планировщика или новых миграций: это версия с регрессионными тестами, не меняющая бизнес-операции.

## Ограничения
Физический CT48, реальные бумажные оригиналы, сканирование и промышленный HTTP-стенд не тестируются. Тесты выполняют Flask test_client и SQLite.
