# lovetech v60 — последовательность завершения производства

На основе v59. Сохранены все предыдущие модули и маршруты.

## Проблема и решение

В v59 строгая проверка требовала закрытия производственного листа **до** регистрации выпуска. В v60 добавлен **явно включаемый** порядок:

1. Оператор фиксирует измерения; технолог/ОТК рассматривает отклонения и регистрирует бумажный оригинал.
2. Лист переводится в `review`.
3. Оператор проводит выпуск; готовая продукция поступает в **карантин**, задание становится `completed`.
4. Технолог сверяет бумажный оригинал и закрывает лист (`closed`).
5. ОТК отдельно разрешает продукцию; выпуск в карантин **не означает** разрешение реализации.

## Конфигурация

По умолчанию `LOVETECH_V60_RELEASE_SEQUENCE=legacy` — прежняя логика без изменений.

Для новой последовательности в окружении приложения задайте **обе** переменные:

```
LOVETECH_V60_RELEASE_SEQUENCE=post_close
LOVETECH_V59_ENFORCE_RELEASE=1
```

В этом режиме выпуск требует утверждённого задания, выданного листа, всех обязательных измерений, отсутствия неразрешённых отклонений, зарегистрированного бумажного оригинала, листа в `review` (или `closed`) и отсутствия подобранной невыданной тары. Расхождения по загрузке — предупреждения, не блокировка. Закрыть лист до выпуска в режиме `post_close` нельзя.

Диагностика: `/production/release-sequence/<номер задания>` (только авторизованные роли). Строгая диагностика v59 остаётся доступной.

**Важно:** режим не меняет историю старых заданий, не переносит данные и не вводит новые таблицы. Настраивайте только после проверки на тестовой копии SQLite. В v60 не добавлена обязательная блокировка ОТК по незакрытому листу; до разрешения продукции проверьте местный регламент.

## Установка

1. Сохраните отдельную резервную копию рабочей SQLite.
2. Разверните архив на тестовом стенде Timeweb с установленными зависимостями `requirements.txt`.
3. Выполните `python -m unittest -v test_v60_sequence`.
4. Проверьте оба режима и действия сотрудников под своими ролями.
5. После согласования технологом включите переменные окружения и перезапустите приложение.

Физический CT48 и полный HTTP-цикл не проверялись в сборочной среде.
