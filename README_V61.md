# lovetech v61 — минимальные остатки и адресные оповещения

Обновление поверх v60. Запуск приложения как прежде: `entrypoint.py` (Dockerfile).
При старте `init()` создаёт три таблицы v61 без изменения существующих остатков.

## Использование

1. Сотрудник с ролью администратора, кладовщика или экономиста открывает `/stock/thresholds`.
2. Выбирает сырьё либо готовую продукцию, позицию, минимум (в единицах справочника), одного или нескольких сотрудников.
3. Сохраняет правило. При `released`-остатке **строго меньше** минимума создаётся событие.
4. Выбранные сотрудники видят его на `/notifications` и могут отметить прочитанным.
5. При восстановлении остатка до порога событие закрывается. При следующем снижении создаётся новое, снова непрочитанное.
6. Изменение получателей действует на текущее активное событие. Отключение правила закрывает событие.

**Важно:** подсчитываются только партии `lots.status='released'` по `lots.qty`, в том числе партии с истёкшим сроком годности (если не сняты с `released`). Это общий учётный остаток, **не** доступный к резервированию FEFO. Не учитываются карантин, резервы и тара по отдельности.

Уведомления внутрисистемные: пересчёт при открытии страницы порогов или уведомлений. Нет push/email/Telegram и периодического фонового опроса.

## Проверка

`python -m unittest -v test_v61_stock_alerts.py`

Для полноценной проверки HTTP: установить `requirements.txt`, развернуть на тестовой базе и проверить роли и CSRF.

Перед обновлением Timeweb сохраните SQLite резервной копией и проверьте обновление на тестовом стенде.
