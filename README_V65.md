# lovetech v65 — доступные остатки и предложения на закупку

На базе v64. Раздел `/stock/planning` доступен администратору, кладовщику и экономисту. В `/stock/thresholds` по-прежнему задаются минимумы и адресаты уведомлений.

Расчёт: только `lots.status=released`, `expires >= сегодня`, за вычетом `reservations` на каждую партию; отрицательные свободные остатки обрезаются до нуля. Уведомления v61 теперь основаны на доступном остатке. Неучтённые физические перемещения и несинхронизированные резервы требуют сверки.

Кнопка создания заявки **только для сырья** создаёт запись `purchase_requests` со статусом `open`; это НЕ заказ поставщику. Количество = max(0, минимум - доступно - открытые заявки - остаток неисполненных заказов). Открытые заявки и заказы не считаются складским запасом. Если заявка уже есть, повторное нажатие не создаст дубль при отсутствии дополнительной потребности. Заявки и заказы, относящиеся к одной потребности, могут учитываться дважды: перед использованием в производстве проверьте бизнес-процесс закупок.

## Установка на Timeweb
1. Сделайте резервную копию SQLite и протестируйте восстановление.
2. Разверните архив вместо предыдущей версии, сохранив `CHEM_DB` и переменные окружения.
3. Перезапустите приложение через `entrypoint.py`, чтобы выполнилась существующая инициализация.
4. Проверьте `/stock/thresholds`, `/stock/planning`, `/notifications` на тестовой базе.

## Тесты
`python -m unittest -v test_v65_stock_planning test_v61_stock_alerts`

Ограничения: нет фонового планировщика или push; нет автоматического создания заказов поставщикам; нет прогноза по производственному плану; расчёт по количеству партий, не по физическим контейнерам. HTTP-тесты требуют Flask и qrcode.
