# lovetech v66 — Контроль ОТК перед отгрузкой

Основа: v65. Добавлена общая проверка допуска `qc_shipping_v66.py`, вызовы в обычной отгрузке `/shipments` и в атомарной QR-отгрузке (используется `/tsd/ship`, `/dispatch/tasks/<id>`, `/dispatch/v32/<id>`), а также SQLite-триггер на `shipments`, блокирующий прямую запись в обход маршрутов.

## Правила допуска
- Только готовая продукция со статусом `released` и действующим сроком годности.
- Для всех активных норм ОТК есть последние положительные результаты в актуальных границах.
- Последняя лабораторная проба, если существует, должна иметь статус `reviewed`.
- Нулевой остаток отклоняется в интерфейсе; количество дополнительно контролируется существующей атомарной операцией списания.

**Важно:** строгая проверка может заблокировать ранее разрешённые партии без результатов ОТК. До развёртывания проверьте исторические данные через `/quality/shipping-control` на тестовой копии. Не меняйте статус партии напрямую в БД.

## Timeweb
1. Создайте и проверьте резервную копию SQLite.
2. Разверните v66 на тестовом стенде с копией БД и теми же переменными окружения, что у v65.
3. При старте `entrypoint.py` вызовет `init()` и установит триггер.
4. Проверьте положительную отгрузку, карантин, просрочку, отсутствие результатов и повторную отгрузку по QR.
5. Только после этого обновляйте рабочую систему.

## Проверки
`python -m unittest -v test_v66_qc_shipping`

Новые тесты SQLite не требуют Flask. HTTP-тесты и CT48 требуют отдельного стенда.
