# lovetech v67 — контроль готовности развёртывания

Основа: lovetech v66. **Новые проверки не меняют производственные маршруты и не исправляют бизнес-логику.** Добавлен независимый от Flask предрелизный барьер `deployment_guard_v67.py`.

## Что проверяет
- Базу SQLite в режиме только чтения: `integrity_check`, внешние ключи и обязательные таблицы.
- Существующую резервную копию: восстановление в изолированную временную SQLite, повторная проверка целостности, SHA-256.
- Свежесть копии (по умолчанию не старше 36 часов).
- Опционально наличие критических Flask-маршрутов (при установленном Flask).
- JSON-отчёт и код завершения `0` только при успешных проверках; иначе `2`.

## Перед обновлением Timeweb
1. Остановите опасные массовые операции и согласуйте окно обслуживания.
2. Создайте резервную копию отдельным именем: `python db_maintenance.py backup --db /app/data/chem.db --output /app/data/backups/before-v67.db`.
3. Скопируйте резервную копию **вне** сервера Timeweb.
4. На тестовом стенде с копией рабочей базы запустите:
   `python deployment_guard_v67.py --db /app/data/chem.db --backup /app/data/backups/before-v67.db --routes --output /tmp/v67-report.json`
5. При коде `2` не обновляйте production. Устраните ошибки, затем повторите проверку.
6. Проверьте в тестовой среде логин по ролям, выпуск, ОТК, отгрузку, табель и Urovo CT48.
7. Разверните обновление в Timeweb и проверьте `/health/ready`, журнал ошибок и реальные сценарии.

## Тесты
`python -m unittest -v test_v67_deployment_guard`

## Ограничения
- Предрелизный барьер не заменяет HTTP-интеграционные тесты, тесты конкурентных операций и проверку на CT48.
- Для `--routes` требуется Flask и зависимости из `requirements.txt`.
- Проверка копии не гарантирует корректность всех бизнес-данных и возможность запуска приложения на этой копии.
- Инструмент не запускает миграции, не переключает production и не отправляет оповещения.
